# رَصْد RASD — نظام تقارير وتشغيل الفروع

نسخة MVP أولية قابلة للتشغيل محليًا. تتضمن:
- لوحة مؤشرات مبنية على التقارير المحفوظة فعليًا.
- نماذج الأنواع الخمسة.
- سجل تقارير مع البحث والتصفية والتفاصيل وإعادة إرسال Telegram.
- إعداد Telegram واختبار الاتصال.
- رفع المرفقات وإرسالها كصور إلى Telegram.
- PostgreSQL عبر Prisma، مع فصل البيانات عن الواجهة.

## المتطلبات
- Node.js 20 أو أحدث
- PostgreSQL 14 أو أحدث
- حساب Telegram وبوت أنشأته عبر BotFather

## التشغيل

1. أنشئ قاعدة بيانات PostgreSQL باسم `rasd`.
2. انسخ ملفات البيئة:

```bash
cp server/.env.example server/.env
cp client/.env.example client/.env
```

3. عدّل `DATABASE_URL` في `server/.env`، وضع مفتاح تشفير عشوائيًا بطول 32 بايت بصيغة hex في `ENCRYPTION_KEY`:

```bash
openssl rand -hex 32
```

4. ثبّت الحزم وجهّز قاعدة البيانات:

```bash
npm install
npm run db:generate
npm run db:push
```

5. شغّل النظام:

```bash
npm run dev
```

- الواجهة: http://localhost:5173
- الخادم: http://localhost:4000
- فحص الخادم: http://localhost:4000/api/health

## إعداد Telegram
من صفحة «الإعدادات» داخل النظام أدخل Bot Token وChat ID ثم اضغط «حفظ الإعدادات» وبعدها «اختبار الاتصال».

للحصول على Chat ID:
- أرسل رسالة إلى البوت أو أضفه إلى المجموعة المطلوبة.
- استخرج `chat.id` من تحديثات البوت باستخدام Telegram Bot API.
- في المجموعات قد يكون Chat ID رقمًا سالبًا.

لا تضع Bot Token في ملفات الواجهة أو متغيرات `VITE_*`. يُخزّن مشفرًا في قاعدة البيانات باستخدام `ENCRYPTION_KEY` الموجود على الخادم.

## ملاحظات مهمة قبل الإنتاج
هذه نسخة تأسيسية وليست نشرًا إنتاجيًا مكتمل الاعتماد:
- لا توجد مصادقة مستخدمين أو أدوار في هذه النسخة؛ لا تعرضها على الإنترنت قبل إضافة تسجيل دخول وصلاحيات.
- ملفات المرفقات محفوظة محليًا في `server/uploads`؛ في الإنتاج استخدم تخزينًا خاصًا مثل S3 مع روابط موقعة.
- أضف HTTPS، وتحديد معدل الطلبات، ونسخًا احتياطيًا لقاعدة البيانات والملفات، وسياسة احتفاظ، ومراقبة للخادم.
- اختبار Telegram الحقيقي يتطلب Bot Token وChat ID صالحين واتصالًا بالإنترنت. لم يتم تنفيذ اختبار حي من بيئة الإنشاء.
- إعادة الإرسال لا تنشئ تقريرًا جديدًا؛ بل تضيف محاولة جديدة في سجل الإرسال.
- لا يوجد حذف للتقارير في الواجهة حاليًا لتجنب الحذف العرضي؛ أضف سير عمل حذف بصلاحيات وتأكيد قبل تفعيله.

## بنية المشروع
- `client/`: تطبيق React وواجهة RTL.
- `server/`: Express API، Prisma، تكامل Telegram، ورفع المرفقات.
